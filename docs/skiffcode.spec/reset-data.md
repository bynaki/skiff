# 데이터 초기화

[목차](../skiffcode.spec.md)

팔레트의 `Reset Data…` 하나다(2026-10-07 사용자 결정). 네이티브 창의 체크리스트에서 고른 항목을 **항목째로** 지운다 — 항목 안에서 하나씩 고르지 않는다. 처음엔 모두 꺼져 있고, 하나라도 켜야 `삭제`가 켜진다. 창 아래에 "Skiff에 있는 서버는 다음 링크 때 프로필과 호스트키를 다시 가져옵니다"를 적는다 — 원격 링크마다 `importFromSkiff`가 돌기 때문이고, Skiff의 것은 다른 앱의 데이터라 여기서 지울 수 없다.

| 항목 | 지우는 것 | 같이 닫는 파일 |
|---|---|---|
| 서버 프로필 | store의 `profiles`(비밀번호째), SFTP 세션 전부 | 원격 파일 — 세션이 없어 저장할 길이 없다 |
| 호스트키 | store의 `knownHosts` | 없음 |
| 프로젝트 | store의 `projects`, 프로젝트 세션과 언어 서버 | 없음 — 사이드바에서 하나 지울 때처럼 열린 채 git 표시만 사라진다 |
| 열린 파일 | 없음 | 전부 |
| 최근 파일 | store의 `recentFiles` | 없음 |
| 설정 | `settings.toml`을 `TEMPLATE`으로 덮어쓰고 언어 서버를 내린다(옛 `[lsp]` 명령으로 떠 있으므로) | 열린 `settings.toml` |
| 테마 | `files/themes/*.toml` 전부. 번들 light/dark는 남는다. 쓰던 테마가 사람 것이면 `theme = "system"` | 열린 사람 테마 파일 |
| 팔레트 최근 기록 | `localStorage`의 `palette.recent` — 명령·파일·심볼 세 모드 다 | 없음 |

- **서버 프로필을 켜면 프로젝트가 켜지고 잠긴다.** 프로젝트는 프로필 id로 서버를 찾아서, 프로필 없이 남으면 열 수 없다. 다른 항목끼리는 서로 가리키는 것이 없다(호스트키는 호스트:포트, 최근 파일은 `user@host` 링크). 프로필을 끄면 프로젝트는 손으로 골랐던 상태로 돌아간다.
- **닫힐 파일 중 저장하지 않은 것이 있으면 이름과 위치를 보이고 한 번 더 묻는다.** 거기서 취소하면 아무것도 지우지 않는다. 버퍼가 고쳐졌는지는 페이지만 알아서, 팔레트가 `resetData`를 부를 때 그런 문서의 id를 함께 보낸다. 창이 떠 있는 동안에는 칠 수 없으니 목록이 바뀌지 않는다.
- store의 네 항목은 한 번의 쓰기로 지운다(`SkiffCodeStore.reset`). 프로필만 지워지고 프로젝트가 남는 중간 상태가 디스크에 남지 않게 하려는 것이다.
