# 파일을 여는 흐름

[목차](../skiffcode.spec.md)

1. 로컬이면 → 단일 파일로 연다.
2. 원격이고 저장된 프로젝트의 루트 아래에 있으면 → 그 프로젝트를 활성화하고 연다.
3. 원격이면 `GitScopeFinder`가 **SFTP만으로** 파일의 디렉토리부터 위로 `.git`(worktree/submodule이면 파일)을 찾는다. **홈 디렉토리(`canonicalize(".")`)에서 멈추고, 홈 밖의 파일은 찾지 않는다.**
   - 홈 자신의 `.git`도 본다(홈을 dotfiles 레포로 쓰는 경우). 파일의 폴더도 `canonicalize`해서 비교하므로, 홈 밖을 가리키는 심볼릭 링크 아래 파일은 홈 밖으로 본다. 이 확인은 SFTP만 쓰므로 exec가 막힌 계정에서도 돈다.
   - `.git`을 찾으면 → "단일 파일로 열기 / 프로젝트 만들기(루트 = git 최상위)"를 묻는다. 뒤로 가기는 단일 파일이다.
   - **"단일 파일로 열기"는 기억하지 않는다**(2026-10-01 사용자 결정). 같은 레포의 파일을 열 때마다, 팔레트로 옆 파일을 열 때도 다시 묻는다.
   - 못 찾으면 → 묻지 않고 단일 파일로 연다.
   - **저장하지 않은 프로필(알 수 없는 서버에서 "프로필로 저장"을 끈 것)에는 프로젝트를 만들지 않는다.** 프로젝트는 프로필 id로 서버를 가리키는데, 그 프로필은 앱이 다시 켜지면 없다.
   - 찾다가 SFTP 오류가 나면 단일 파일로 연다. 프로젝트 없이 열리던 예전과 같다.
4. 프로젝트를 활성화할 때 `RemoteExec.supported()`로 exec가 되는지 본 뒤 `command -v git`을 확인한다. exec가 안 되면(internal-sftp, nologin) git/LSP 없이, git이 없으면 git 없이 열고 이유를 배너로 알린다. 확인이 실패하면(연결, 시간 초과) 일단 git 없이 열고 다음 활성화 때 다시 확인한다.
   - 확인은 프로젝트마다 프로세스에서 한 번이고(`ProjectSessions`), 배너도 그때 한 번이다. 프로젝트의 파일을 열 때마다 같은 말을 하지 않는다.
   - 프로젝트는 `SkiffCodeData.projects`에 프로필 id와 canonical 루트로 저장한다(`ProjectStore`). 2단계는 파일의 폴더를 `canonicalize`해서 루트와 비교하고, 루트가 겹치면 가장 깊은 것을 고른다.

## 같은 서버의 다른 주소

한 서버를 도메인, 테일스케일 별칭, 테일스케일 주소로 열면 프로필이 셋으로 갈린다. 프로젝트를 프로필 id로만 찾으면 같은 레포가 주소마다 "프로젝트 만들기"를 다시 묻고 사이드바에 여러 번 생긴다(`my.next.spec.md`의 "fix: 02").

- **2단계의 "같은 서버"는 호스트 키로 가린다.** 열린 파일이 같은 파일인지 가리는 것([`document-io.md`](document-io.md), 2026-09-30 사용자 결정)과 같은 기준이다. 파일을 연 프로필의 호스트 키(`stat`이 호스트 키 창을 지난 뒤라 `knownHosts`에 있다)와 같은 지문을 가진 프로필들 가운데, 아래의 물음에서 "같은 서버"로 이어진 것들이 한 서버다. 그 프로필들의 프로젝트가 모두 후보다. 지문은 프로젝트에 따로 적지 않고 그때 각 프로필의 `host:port`로 `knownHosts`에서 읽는다 — 프로젝트의 저장 형식이 바뀌지 않고, 이미 있는 프로젝트도 그대로 맞는다.
  - 사용자 이름은 보지 않는다(열린 파일과 같다). 지문이 없으면(호스트키를 지운 뒤 아직 접속하지 않은 프로필) 그 프로필은 자기만의 서버다.
- **호스트 키가 같아도 다른 기계일 수 있어 한 번 묻는다**(2026-10-14). Docker 이미지가 `apt-get install openssh-server`나 `ssh-keygen -A`를 빌드 때 하면 키가 이미지에 구워져 그 이미지의 컨테이너가 모두 같은 키를 쓴다. VM 이미지를 복제해도 같다.
  - 저장된 프로필로 파일을 열 때, 지문이 같은 다른 저장된 프로필이 있는데 그쪽과 아직 답이 없으면 연결 뒤·파일을 읽기 전에 네이티브 창으로 묻는다: "`<이 프로필>`은 `<그 프로필>`과 호스트 키가 같습니다. 같은 기계입니까?" `같은 서버` / `다른 서버`. 뒤로 가기는 `다른 서버`로 보고 기억하지 않는다(다음에 다시 묻는다).
  - 답은 프로필 둘의 짝으로 store에 남긴다(`SkiffCodeData`의 새 목록, 프로필 id 둘과 같은지). 묻는 단위는 프로필 하나가 아니라 **이미 묶인 무리 하나**다: 무리 안에서 이미 답이 있는 짝은 다시 묻지 않고, "같은 서버"는 무리 전체로 이어진다. 그래서 세 주소의 서버도 처음 한두 번만 묻는다.
  - 서버의 이름(열린 파일의 `keyOf`, 프로젝트 찾기가 쓰는 것)은 지문과 무리의 대표 프로필 id다. 대표는 store 목록에서 먼저 있는 프로필이다 — 새 프로필은 끝에 붙으므로 무리가 커져도 대표가 바뀌지 않는다.
  - 저장하지 않은 프로필(알 수 없는 서버에서 "프로필로 저장"을 끈 것)은 묻지 않고 자기만의 서버로 본다. 답을 남길 곳이 없고, 그런 프로필에는 프로젝트도 없다. 지금(M4)은 지문만으로 다른 프로필의 열린 파일과 합쳐졌는데, 이제 합쳐지지 않는다.
  - 답은 신원 확인이 아니다. 접속마다 호스트 키 창(`HostKeyGate`)이 그대로 지문을 확인하고, 이 답은 같은 지문의 두 주소를 화면에서 하나로 볼지만 정한다. 잘못 답하면 열린 파일과 프로젝트가 합쳐지거나 갈릴 뿐이다.
  - 답을 바꾸는 길은 `Reset Data…`의 "서버 프로필"뿐이다(답은 프로필과 함께 지워진다). `importFromSkiff`는 프로필을 지우지 않지만 주소(`host`·`port`)를 바꿀 수 있다 — 그때 그 프로필의 답을 뺀다. 다른 곳을 가리키게 된 프로필에 옛 답이 남지 않게 하려는 것이다.
- **프로젝트의 git·LSP 연결은 프로젝트를 만든 프로필로만 한다**(2026-10-13 사용자 결정). 다른 주소로 그 프로젝트의 파일을 열어도 `ProjectSessions`의 세션을 바꾸지 않아 LSP가 다시 뜨지 않는다. 그 주소가 끊기면 git·LSP만 안 되고 파일은 연 주소로 열린다. 사이드바 트리와 거기서 여는 파일도 지금처럼 프로젝트의 프로필로 간다.
- **이미 중복으로 만들어진 프로젝트는 코드가 합치지 않는다**(2026-10-13 사용자 결정). 새 중복만 막고, 있는 것은 사이드바에서 길게 눌러 지운다. 열 때는 후보 가운데 가장 깊은 루트를, 같은 루트가 여럿이면 먼저 만든 것을 고른다.

## 성공 조건

이 주제가 됐다고 말할 수 있는 조건과 확인 방법이다(`AGENTS.md`). ✅는 충족, ⬜는 아직이다. 확인한 때와 자세한 내역은
[`skiffcode.plan.done.md`](../skiffcode.plan.done.md)의 그 마일스톤에 있다.

- ✅ git 레포 안의 원격 파일을 열면 "단일 파일로 열기 / 프로젝트 만들기"를 묻고, 홈 밖과 `.git`이 없는 곳에서는 묻지 않는다 — 확인: `GitScopeFinderTest`(MINA: 홈 경계, worktree의 `.git` 파일, 홈 밖), 탭(M5).
- ✅ 저장된 프로젝트 아래 파일은 묻지 않고 그 프로젝트로 열린다. 루트가 겹치면 가장 깊은 것이다 — 확인: `ProjectStoreTest`, 탭(M5).
- ✅ exec가 안 되는 계정(internal-sftp, nologin)과 git이 없는 서버에서도 프로젝트가 git·LSP 없이 열리고 이유가 배너로 한 번 뜬다 — 확인: `RemoteExecTest`, `CheckGitTest`, Docker 계정 셋으로 탭에서(M5).
- ⬜ 호스트 키가 같고 `같은 서버`라 답한 다른 프로필로 같은 레포의 파일을 열면 "프로젝트 만들기"를 묻지 않고 있는 프로젝트로 열리고, 사이드바의 프로젝트가 늘지 않는다. 지문이 다르거나 없으면 지금처럼 따로다 — 확인: `ProjectStoreTest`, 탭(이 맥을 두 주소로)(F2).
- ⬜ 다른 주소로 열어도 프로젝트의 git·LSP 세션은 만든 프로필의 것 그대로이고 LSP가 다시 뜨지 않는다 — 확인: 탭(이 맥에서 LSP 프로세스 id가 그대로)(F2).
- ⬜ 호스트 키가 같은 다른 기계(같은 이미지의 Docker 컨테이너 둘)는 한 번 묻고, `다른 서버`라 답하면 같은 경로라도 프로젝트와 열린 파일이 따로다. 답은 다시 묻지 않고, `같은 서버`라 답한 무리의 세 번째 주소는 한 번만 묻는다 — 확인: JVM(무리 묶기·물을 것 고르기), 탭(F2).
- ⬜ 사용자의 실제 서버를 세 주소로 열어 사이드바에 프로젝트가 하나다(이미 있던 중복을 손으로 지운 뒤) — 확인: 사용자가 폴드8에서(F2).
