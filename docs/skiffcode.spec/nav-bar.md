# 오른쪽 네비게이션 바

[목차](../skiffcode.spec.md)

원래 요구사항은 [`my.next.spec.md`](../my.next.spec.md)의 "오른쪽에 가는 막대 네비게이션 바"다. 화면 오른쪽 가장자리의 가는
막대 하나에 **그 문서 전체**의 변경을 줄여 그려, 스크롤하지 않고도 어디가 바뀌었는지 한눈에 본다. VS Code의 overview
ruler와 같은 것이다.

- **보이는 것은 git 변경과 LSP 진단이다**(2026-10-21 사용자 결정).
  - git 변경은 [git 거터](git.md)와 같은 것이다: HEAD와 비교해 추가·수정된 줄과 지운 줄의 자리. 같은 `baselineField`의
    청크(`gitMarks`)를 쓰므로 거터와 막대가 다를 수 없다. 기준이 없으면(프로젝트가 아님, HEAD에 없는 파일) git 표시가 없다.
  - 진단은 `@codemirror/lint`의 상태(`forEachDiagnostic`)에 든 것이다. **오류와 경고만** 그린다 — info·hint까지 그리면
    막대가 덮인다(2026-10-21 사용자 확인).
  - 색은 거터와 같은 테마 변수다: 추가 `--diff-added`, 수정 `--diff-changed`, 지운 줄 `--diff-removed`, 오류 `--syntax-invalid`.
    **경고는 테마에 새로 둔 `[syntax] warning`이다**(2026-10-21 사용자 결정). 번들 값은 다크 `#d29922`, 라이트 `#9a6700`이고, 이 키가
    없는 사용자 테마는 다른 빠진 색처럼 base의 값을 받는다. 렌더된 hover의 경고 글자색은 바꾸지 않았다.
- **지금 화면에 보이는 구간을 막대 위에 옅은 상자로 그린다**(2026-10-21 사용자 결정). 스크롤과 핀치를 따라 움직인다.
- **터치는 받지 않는다**(요구사항). 막대는 `pointer-events: none`이라 그 자리의 탭과 끌기는 뒤의 문서가 받는다. 시스템 뒤로
  가기 제스처의 오른쪽 가장자리([점프 목록](jumps.md))와 겹치지 않는 까닭이기도 하다.
- **viewer·editor·diff에 두고, 마크다운 viewer에는 없다**(2026-10-21 사용자 결정). git 거터와 같은 범위다. 렌더된 마크다운은
  CodeMirror가 아니라서 원문 줄의 높이를 알 수 없다. 그래서 레이어 compartment 밖, 설정 compartment(`settings.ts`)에 든다.
- **켜져 있으면 브라우저의 스크롤바를 숨긴다**(2026-10-21 사용자 결정). 막대가 화면이 어디인지 말하므로 둘은 겹친다. 세로 스크롤바만
  숨고 가로 스크롤바(`wrap = false`)는 남는다 — 아래 "어떻게 거는가"의 방법이 오른쪽 끝만 자르기 때문이다. 끄면 스크롤바가 돌아온다.
- **`settings.toml`의 `[editor] nav_bar`, 기본은 끔이다**(2026-10-21 사용자 결정, [설정과 테마](settings-theme.md)). 저장하면 바로
  적용된다. 켜져 있으면 코드 레이어에서는 표시가 없어도 막대(보이는 구간 상자)가 있다(2026-10-21 사용자 확인).

## 어떻게 거는가

- **세로 위치는 줄 번호가 아니라 높이 지도로 정한다.** 한 표시의 높이는 `lineBlockAt(pos).top / contentHeight`의 비율이다.
  그래야 줄바꿈된 긴 줄, diff 레이어의 지운 줄 위젯, 접힌 구간이 들어가도 막대가 스크롤 위치와 맞고, 보이는 구간 상자
  (`scrollTop / scrollHeight`)와 같은 자를 쓴다. 화면 밖 줄의 높이는 CodeMirror의 추정이라 큰 파일에서는 스크롤하며 조금
  움직일 수 있다.
- **그리기는 `ViewPlugin` 하나(`navBar.ts`)가 `view.dom`(스크롤되지 않는 쪽)에 둔 `<canvas>`와 상자 `<div>`로 한다.** 진단이 수천 개여도
  요소 수가 늘지 않게 캔버스에 그리고, 같은 픽셀 줄에 걸린 표시는 칸마다 하나로 합친다(진단 칸에서는 오류가 경고를, git 칸에서는
  지운 줄이 수정을, 수정이 추가를 이긴다). git은 막대의 왼쪽 절반, 진단은 오른쪽 절반에 그려 둘이 겹쳐도 다 보이게 한다(2026-10-21 사용자 확인).
  - 다시 그리는 때: 문서·높이(`geometryChanged`)·기준·진단이 바뀔 때, 크기가 바뀔 때. 읽기는 `requestMeasure`의 `read`에서,
    그리기는 `write`에서 한다. 스크롤에는 상자만 옮긴다(`transform`).
  - 캔버스는 CSS 변수를 읽지 못하므로 그릴 때마다 색을 `getComputedStyle`로 읽는다. 테마가 바뀌면 설정 compartment가 다시
    걸리고(`reconfigured`), 그것이 다시 그리게 한다. 색은 코드에 `var(--…)`로 적어 둔다 — `theme.test.ts`가 그 모양으로 페이지가
    읽는 테마 색을 센다.
  - **변경이 빽빽하면 한 줄기가 된다.** 표시는 적어도 2px이라, 1만 9천 줄 파일에서 50줄마다 바뀐 줄(막대에서 1.6px 간격)은
    git 칸 전체가 하나로 이어져 그려진다(탭, 2026-10-21). 2px보다 촘촘한 것을 따로 보여 줄 수는 없다.
- **막대의 자리:** 오른쪽 끝(`right: 0`, `position: fixed`), 위는 상단 메뉴 아래(`--topbar-space`), 아래는 배너 위(`--banner-space`).
  폭은 6px(`NAV_BAR_WIDTH`, 2026-10-21 사용자 확인)이고 git 칸·진단 칸이 3px씩이다. 우하단 커맨드 버튼은 오른쪽에서 16px 떨어져 있어 겹치지
  않는다. 상단 메뉴가 스크롤로 물러나도 막대의 위 끝은 그대로다. 마크다운 viewer에서는 `view.dom`이 `display: none`이라 막대도
  같이 숨는다.
- **스크롤바는 CSS로 끌 수 없어서 화면 밖으로 밀어 자른다.** Android WebView(탭의 Chrome 155)는 `scrollbar-width`를 모르고
  (`CSS.supports`가 false, 규칙이 버려진다) `::-webkit-scrollbar { display: none }`도 무시하고 오버레이 스크롤바를 그렸다. 그래서
  막대가 켜져 있으면 `.cm-scroller`에 `margin-right: -24px`를 주어 오른쪽으로 24px 넓히고(`SCROLLBAR_TUCK`), `.cm-editor`가 그 밖을
  자른다. 스크롤바의 손잡이는 오른쪽 끝에서 10px쯤 안쪽에 그려져 24px이면 다 잘린다.
  - **`overflow: clip`이어야 한다. `hidden`은 안 된다.** `hidden`인 상자는 스크립트로 스크롤될 수 있어서, 커서를 화면 안으로
    들이는 스크롤이 `.cm-editor` 자체를 24px 옆으로 밀었고(탭, `wrap = false`) 스크롤바가 다시 화면에 들어왔다. `clip`은 스크롤
    상자가 아니다.
  - 툴팁은 `position: fixed`라 이 자르기에 걸리지 않는다.
- **글자가 막대 밑으로 들어가지 않게** 켜져 있을 때 `.cm-content`의 `padding-right`와 `scrollMargins.right`에 막대 폭과 밀어 낸 24px을 더한다(`NAV_BAR_ROOM` 30px)
  ([문서 여백](margins.md)의 `sidescrolloff`에 더하는 것이고, `wrap = true`이면 막대 폭만). 같은 설정 compartment에 들어
  세 레이어의 줄바꿈 폭이 같다는 것은 그대로다.

## 성공 조건

이 주제가 됐다고 말할 수 있는 조건과 확인 방법이다(`AGENTS.md`). ✅는 충족, ⬜는 아직이다. 확인한 때와 자세한 내역은
[`skiffcode.plan.done.md`](../skiffcode.plan.done.md)의 그 마일스톤에 있다.

- ✅ (2026-10-21, JVM 331·`:code` 린트 경고 11 그대로) JVM: `nav_bar`의 기본값(끔), 타입이 틀리면 전부 기본값, `KEYS`와 `Settings`가 같다 — 확인: `SettingsTomlTest`. `:code` 린트에 새 경고가 없다.
- ✅ (2026-10-21, vitest 208) vitest: 표시를 막대의 픽셀 줄로 바꾸는 계산(git 추가·수정·삭제, 진단 오류·경고, info·hint는 없음, 같은 픽셀 줄은 하나로, 빈 문서와 한 줄 문서), 보이는 구간 상자의 위치와 높이 — 확인: 새 테스트 `navBar.test.ts`, 오른쪽 여백은 `margins.test.ts`.
- ✅ (탭, 2026-10-21 — 숫자는 `skiffcode.plan.done.md`의 M12) 탭, `nav_bar = true`, git 프로젝트의 파일: 맨 위·가운데·맨 끝의 변경이 막대의 같은 비율 높이에 보이고, 스크롤해 가 보면 git 거터의 표시와 맞는다. LSP 오류·경고가 보인다. 편집하면 막대가 바로 바뀐다. 보이는 구간 상자가 스크롤과 핀치를 따른다. viewer·editor·diff에 있고 마크다운 viewer에는 없다. 막대를 탭하거나 끌면 문서가 받고, 오른쪽 가장자리의 뒤로 가기 제스처는 그대로다. 글자가 막대에 가리지 않는다(`wrap` 양쪽).
- ✅ (탭, 2026-10-21) 탭: `nav_bar = false`(기본)이면 지금과 같고, 저장하면 바로 켜지고 꺼진다.
