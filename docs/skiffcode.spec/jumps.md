# 전 화면, 앞 화면 (점프 목록)

[목차](../skiffcode.spec.md)

vim의 `Ctrl+O`(전 화면으로)와 `Ctrl+I`(앞 화면으로)다. 원래 요구사항은 [`my.next.spec.md`](../my.next.spec.md)에 있다. viewer, editor, diff 어느 레이어에서나 동작하고 파일 사이도 오간다. 손으로는 제스처로 한다: **화면 오른쪽 가장자리에서 왼쪽으로 밀면 전 화면, 왼쪽 가장자리에서 오른쪽으로 밀면 앞 화면**이다.

- **제스처는 시스템의 뒤로 가기로 받는다.** 제스처 내비게이션에서 양쪽 가장자리를 안쪽으로 미는 것은 시스템의 뒤로 가기라, 페이지의 터치 처리에는 오지 않는다. 대신 Android 14(API 34)부터 `OnBackAnimationCallback.onBackStarted`의 `BackEvent.getSwipeEdge()`가 어느 쪽에서 시작했는지 알려 준다.
  - `EDGE_RIGHT` → 전 화면, `EDGE_LEFT` → 앞 화면.
  - `EDGE_NONE`(3버튼 내비게이션의 뒤로 버튼)과 API 34 미만 → 전 화면. 이때 앞 화면은 키와 팔레트로만 간다.
  - `MainActivity`는 `ComponentActivity`가 아니라 `Activity`라서 androidx의 `OnBackPressedDispatcher`가 아니라 플랫폼의 `onBackInvokedDispatcher`에 건다.
  - 삼성의 "아래에서 스와이프" 모드나 3버튼 모드에서도 앞 화면 스와이프가 필요한지는 **두 기기의 내비게이션 모드를 확인한 뒤 정한다**(2026-10-11 사용자 결정). 필요하면 그 모드에서만 페이지가 가장자리 스와이프를 직접 받는다 — 시스템이 가장자리를 가져가지 않으니 받을 수 있다.
- **콜백은 쓸 데가 있을 때만 켠다.** 페이지가 `navigationState {back, forward, overlay}`를 알리고, Kotlin은 셋 중 하나라도 참일 때 콜백을 등록한다. 셋 다 거짓이면 지금처럼 시스템의 뒤로 가기(홈으로 가는 애니메이션까지)가 그대로 동작한다. 앞 화면만 있을 때 오른쪽에서 밀면 아무 데도 가지 않는다.
- **사이드바, 팔레트, 열린 파일 메뉴, 더보기 메뉴가 나와 있으면 어느 쪽에서 밀든 그것부터 닫는다.** Android의 관례다. 소프트 키보드는 시스템이 먼저 닫는다.
- **점프 목록은 페이지가 갖는다**(`web/src/jumps.ts`). 한 칸은 `{파일 id, 화면 맨 위의 원본 줄}`이다. 줄은 `topLine()`이 읽는 것이라 viewer, editor, diff, 렌더된 마크다운 어디서 읽어도 같은 원본 줄이다.
  - vim과 같이 **움직이기 직전의 자리**를 적는다. 끝에서 뒤로 가면 지금 자리를 먼저 적어서, 앞 화면으로 다시 돌아올 수 있다.
  - 뒤로 간 채 새로 움직이면 그 앞의 칸은 버린다(브라우저의 방문 기록과 같다). 같은 파일의 같은 줄이 이어지면 하나로 합친다. 100칸을 넘으면 오래된 것부터 버린다.
  - **메모리에만 둔다.** 파일 id는 Kotlin이 프로세스 안에서 매기는 번호라, `localStorage`에 적어도 다음 실행에서는 다른 파일을 가리킨다.
- **적는 때는 두 곳이다.**
  - 화면의 파일이 바뀔 때: 링크, 열린 파일 메뉴, 팔레트 파일 모드, 사이드바, 다른 파일의 정의, 프로젝트 심볼이 모두 `main.ts`의 `reconcile`을 지나므로 거기서 적는다.
  - 같은 파일 안에서 줄을 옮길 때: 링크의 `?line=`, 같은 파일의 정의, 심볼 모드. `goToLine` 바로 앞에서 적는다.
  - 스크롤과 레이어 전환은 적지 않는다. 점프 목록으로 움직인 것도 적지 않는다.
- **점프 목록으로 움직이는 길.** 같은 파일이면 `goToLine`이다. 다른 파일이면 `activate`에 `goToLine`을 실어 보내고, Kotlin은 그것을 `documentsChanged`에 실어 돌려준다. 링크가 줄을 가져오는 길과 같은 한 길이다. 줄은 맨 위로 올리고, 커서도 그 줄로 옮긴다.
- **레이어는 적지 않는다**(2026-10-11 사용자 결정). 돌아간 파일은 지금 있는 레이어 그대로 그 줄을 보인다.
- **닫힌 파일을 가리키는 칸은 건너뛴다**(2026-10-11 사용자 결정). 파일이 닫히면 그 칸은 목록에서 빠진다. vim처럼 다시 여는 것은 미뤘다: Kotlin이 닫힌 파일의 여는 요청을 들고 있다가 페이지가 그 손잡이만 보내 다시 여는 길이 새로 필요하고, 그것은 "Links that arrive from outside"(`AGENTS.md`)가 말하는, 페이지가 보낼 수 있는 것을 넓히는 일이다.
- **키와 팔레트.** 하드웨어 키보드의 `Ctrl+O`/`Ctrl+I`, 팔레트의 `Go Back`/`Go Forward`. CodeMirror 기본 키맵에서 `Mod-i`는 `selectParentSyntax`이므로 점프 키를 더 높은 우선순위로 덮는다.
