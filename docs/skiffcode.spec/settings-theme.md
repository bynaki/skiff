# 설정과 테마

[목차](../skiffcode.spec.md)

- `settings.toml`: 폰트, 폰트 크기, 탭 크기, 줄바꿈, 테마, diff 투명도, 크기 상한, 열린 파일 상한(`kept_buffers`), 폴링 주기, git 없는 프로젝트의 파일 검색(`[search]`, [팔레트](palette.md)). LSP 명령은 **그것을 읽는 기능과 함께 들어온다**(2026-09-27 사용자 결정) — 읽는 곳이 없는 키는 적어도 아무 일도 일어나지 않는다. M6에서 `[lsp]`가 들어왔다([LSP](lsp.md)의 페이지 쪽).
  - **문서 여백은 `[editor] scrolloff`(줄, 0~50, 기본 5)와 `[editor] sidescrolloff`(글자, 0~100, 기본 5, `wrap = true`이면 쓰지 않는다)이다**(2026-10-20 사용자 결정. M10의 px `right_margin`을 M11에서 바꿨다). 무엇을 하는지는 [문서 여백과 scrolloff](margins.md).
  - **오른쪽 네비게이션 바는 `[editor] nav_bar`(참/거짓, 기본 끔)이다**(2026-10-21 사용자 결정, M12). 무엇을 하는지는 [오른쪽 네비게이션 바](nav-bar.md).
  - **diff 투명도는 `[editor] diff_alpha`, 퍼센트 정수 0~100, 기본 30이다**(2026-10-03 사용자 결정). 처음엔 0~50에 15였는데, 줄 배경 위에 글자 배경이 겹쳐 진해서 10으로 낮췄다가, 글자 배경을 없애고 줄 배경만 남기니 옅어 30으로 올렸다. 상한 50은 "글자는 두 배로 칠한다"가 이유였는데 그것이 없어져 100이 됐다. 다른 키처럼 정수 범위로 검사한다. 페이지는 `--diff-alpha`(0~1)로 받는다.
  - **앱 내부(`filesDir`)에 두고 팔레트의 `Open Settings`로 앱 안에서 편집한다**(2026-09-27 사용자 결정). **저장하는 것이 적용이다.**
  - **파일의 키는 모두 주석 처리된 기본값으로 보여 준다**(2026-10-03 사용자 결정). 키마다 설명과 범위, `Default: …`를 적은 주석 아래에 `# key = 기본값` 줄을 둔다. `#`를 떼고 값을 바꾸는 것이 설정이다. 주석으로 두는 까닭은, 파일에 값으로 적혀 있으면 다음 버전에서 기본값을 바꿔도(`diff_alpha` 10 → 30) 그 파일에는 닿지 않기 때문이다.
  - **`Open Settings`로 열 때 파일에 없는 키를 같은 모양으로 채운다**(2026-10-03 사용자 결정). 처음이면 모든 키가 든 파일을 만들고, 이전 버전이 만든 파일이면 빠진 키만 자기 표의 끝에 넣는다(표가 없으면 표째 파일 끝에). 주석 처리된 줄도 "있는 것"으로 쳐서 두 번 넣지 않는다. 사람이 쓴 줄과 값은 건드리지 않고, TOML로 읽히지 않는 파일은 손대지 않는다. 열지 않으면 파일은 그대로다. 키 줄을 아예 지우면 다음에 열 때 주석으로 돌아온다. 앱 밖으로 꺼내고 들이는 것은 아래 SAF import/export의 일이다. 공유 저장소에 두면 다른 편집기로도 열리지만 모든 파일 권한이 필요하고 앱 밖에서 바뀐 것도 감시해야 한다.
  - **잘못된 값:** 범위 밖이나 빈 글꼴은 그 키만 기본값으로 쓰고, 타입이 틀리거나 TOML이 깨졌거나 **모르는 키**가 있으면 전부 기본값으로 쓴다. 어느 쪽이든 저장한 자리에서 배너로 무엇을 버렸는지 알린다. 모르는 키를 건너뛰지 않는 것은 오타가 가장 흔할 것이기 때문이다.
  - **줄바꿈은 기본으로 켠다**(2026-09-27 사용자 결정). 폴더블 커버 화면(475dp)에서 가로 스크롤로는 한 줄이 오른쪽으로 사라진다. 코드를 가로로 보고 싶은 사람은 `wrap = false`로 끈다. 렌더된 마크다운의 코드 블록도 같이 따른다.
  - 폰트 크기에는 **기기의 시스템 글꼴 배율이 그대로 곱해진다.** `font_scale` 1.5인 폰에서 기본 14px이 21px로 나왔다(WebView의 `textZoom`, 페이지 아래에서 적용되어 페이지가 볼 수 없다). 설정의 상한 8~40도 그만큼 달라진다. **따르기로 했다**(2026-09-27 사용자 결정) — 글자를 크게 해 둔 사람은 코드도 크게 본다. 대신 `font_size`가 기기마다 다른 크기가 된다.
  - `font_size`는 Reset Zoom이 돌아가는 크기다. 핀치한 크기(`localStorage`의 `zoom.size`)는 따로 남고, 설정의 크기가 **바뀌었을 때**와 핀치한 적이 없는 **첫 실행**에만 지금 크기도 그리로 옮긴다.
- `themes/*.toml`: `[ui]`(메뉴, 사이드바, 팔레트), `[editor]`, `[syntax]`, `[diff]`. Web에서 CSS 변수로 바꾸고 **메뉴와 레이어에 똑같이** 적용한다. 다크와 라이트를 기본 번들한다. 잘못된 값은 기본값으로 폴백하고 오류를 알린다.
  - **고르는 것은 `settings.toml`의 `[editor] theme`이고 기본값은 `system`이다**(2026-09-28 사용자 결정). `system`은 기기의 다크 모드에 맞는 번들을 쓴다. 팔레트의 `Theme: …` 명령이 그 줄을 고쳐 쓴다. 사용자 테마는 import와 함께 들어온다.
    - **M13에서 커뮤니티 테마 45개를 공개 저장소에 모으고 앱에서 `Download Theme...`으로 골라 받는다. 번들은 `light`·`dark` 그대로이고, `Theme: …` 명령들은 팔레트의 `Theme...` 목록 하나로 바뀐다**(2026-10-22 사용자 결정). 받은 테마는 가져온 테마와 같은 사용자 테마다. 자세한 것은 [커뮤니티 테마와 테마 목록](community-themes.md).
  - 검사와 폴백은 Kotlin(`settings/Theme.kt`)이 한다. 빠진 색과 쓸 수 없는 색은 같은 `base`의 번들 값이고, 모르는 키가 있으면 base 전체다 — `settings.toml`과 같은 규칙이다. 페이지는 온전한 한 벌을 받아 변수로 쓴다.
  - 다크 모드는 `uiMode`로 Kotlin이 읽는다. WebView의 `prefers-color-scheme`는 앱 테마를 따르지 기기를 따르지 않을 수 있고, 액티비티를 다시 만들지 않으려면 어차피 `onConfigurationChanged`를 받아야 한다.
- 설정과 테마의 import/export는 SAF(`ACTION_OPEN_DOCUMENT` / `ACTION_CREATE_DOCUMENT`)로 한다. 팔레트의 `Import Settings`, `Export Settings`, `Import Theme`, `Export Theme`.
  - **가져온 테마의 이름은 파일 이름이다**(2026-09-28 사용자 결정). `ocean.toml`은 `filesDir/themes/ocean.toml`에 쓴 그대로 들어가고, 팔레트에 `Theme: ocean`이 생기며 바로 그 테마가 된다(`theme = "ocean"`). 같은 이름이 있으면 덮어쓸지 묻는다. 이름은 글자·숫자·공백·`_`·`-`·괄호만(`ocean (1).toml`도 들어오게), `system`/`light`/`dark`는 안 된다 — 파일 경로와 `theme = "…"`에 그대로 쓰이기 때문이다.
  - **설정과 테마를 따로 내보낸다**(2026-09-28 사용자 결정). `Export Theme`는 지금 화면의 테마(`system`이면 따르고 있는 번들)를 원문 그대로 낸다. 번들을 내보내 고쳐서 들이는 것이 사용자 테마를 만드는 길이다.
  - **가져온 파일은 저장과 같은 규칙이다**(2026-09-28 사용자 결정). 문제가 있어도 들이고, 버린 값은 닫기 붙은 배너로 알린다. 잘 되면 2.5초 배너다.
- 팔레트의 `Copy Theme`, `Edit Theme`, `Delete Theme`(2026-09-29 사용자 요청). **셋 다 지금 화면의 테마를 대상으로 한다**(2026-09-29 사용자 결정) — `Export Theme`과 같고, 테마마다 명령을 늘리면 팔레트가 붐빈다.
  - **기본 테마는 고칠 수도 지울 수도 없다.** 번들은 APK의 assets라 쓸 수 없고 이름은 `nameOf`가 막는다. 번들에서 `Edit Theme`은 복사를 권하고, `Delete Theme`은 팔레트에 뜨지 않는다(`settings` 답의 `ownTheme`). 복사본은 그 사람 것이라 앱이 업데이트되며 번들 색이 바뀌어도 따라가지 않는다.
  - **`Copy Theme`:** 이름은 네이티브 입력 창에서 받는다(2026-09-29 사용자 결정). `dark copy`처럼 채워 두고, `nameOf`가 거절하면 까닭을 붙여 다시 묻는다. 같은 이름이 있으면 바꿀지 묻는다. 원문을 그대로 `filesDir/themes`에 쓰고, **그 테마로 바꾼 뒤 편집기로 연다** — 복사하는 까닭이 거의 고치기 위해서다.
  - **`Edit Theme`:** 테마 파일을 `Open Settings`처럼 앱 안에서 연다(`OpenFlow.openOwn` — 경로 확인 창·권한·폴더 없음). **저장하는 것이 적용이다.** 그 테마만 다시 읽어 `settingsChanged`를 보내고, 문제는 저장 답의 `warning`에 싣는다. 편집 중 오타도 **가져올 때와 같은 규칙이다**(2026-09-29 사용자 결정): 모르는 키 하나면 base 전체, 배너가 키를 말한다.
  - **`Delete Theme`:** 확인 창 뒤에 지우고 `theme = "system"`으로 돌린다. 그 파일이 열려 있으면 친 것째로 닫는다 — 두면 "이 파일이 사라졌습니다" 배너가 뜬다. 이름 바꾸기는 따로 두지 않는다(복사 뒤 삭제).
- TOML 파싱은 Kotlin의 ktoml(`com.akuleshov7:ktoml-core` 0.7.1)로 한다. M0에서 확인했다.
  - 중첩 테이블, 문자열 리스트, 언어로 키를 삼은 테이블(`[lsp.python]` → `Map<String, …>`),
    빠진 키의 생성자 기본값이 모두 된다.
  - `:code`에 kotlinx.serialization 플러그인이 필요하다. **KSP는 아니라서 Room과 달리 문제가 없다.**
  - ktoml은 kotlinx-serialization-core 1.9.0으로 빌드됐는데, M2에서 `:code`에 serialization-json
    1.11.0이 들어오면 core가 1.11.0으로 올라간다. 그 조합으로도 테스트가 통과한다.
  - `kotlinx-datetime`이 함께 들어온다. 설정에 날짜가 없어도 APK에 들어간다.

## 성공 조건

이 주제가 됐다고 말할 수 있는 조건과 확인 방법이다(`AGENTS.md`). ✅는 충족, ⬜는 아직이다. 확인한 때와 자세한 내역은
[`skiffcode.plan.done.md`](../skiffcode.plan.done.md)의 그 마일스톤에 있다.

- ✅ `settings.toml`의 키가 왕복되고, 없는 키는 기본값, 범위 밖은 그 키만, 타입 오류·깨진 TOML·모르는 키는 전부 기본값이며 배너로 알린다 — 확인: `SettingsTomlTest`, `SettingsFileTest`.
- ✅ `Open Settings`로 열 때 빠진 키가 주석 처리된 기본값으로 채워진다 — 확인: `SettingsTomlTest`(빠진 키 채우기, 두 번 해도 같음, 주석으로 둔 키 유지), `SettingsFileTest`(M5).
- ✅ 저장하면 바로 적용된다(`poll_seconds`, `kept_buffers`, `font_size`, `wrap`, `diff_alpha`) — 확인: 탭(M4, M5).
- ✅ 테마를 바꾸면 메뉴·사이드바·팔레트·레이어가 한꺼번에 바뀌고, 잘못된 색은 번들 값으로 폴백한다 — 확인: `ThemeTomlTest`, `ThemesTest`, vitest `theme.test.ts`, 탭과 폴드8(M4).
- ✅ 설정·테마 import/export, `Copy`·`Edit`·`Delete Theme`, 기본 테마 보호가 된다 — 확인: `ThemesTest`, 탭과 폴드8(내보낸 파일의 md5가 같음, M4).
