# 커맨드 버튼과 팔레트 (VS Code 커맨드 팔레트 방식)

[목차](../skiffcode.spec.md)

- **A:** 우하단 버튼. 평소에는 50% 투명도이고, 누르면 100%가 되며 B로 간다.
- **B:** 입력 커서가 활성화되고 버튼은 "입력 버튼"이 된다.
  - 빈 곳을 누르는 등으로 취소하면 A로 돌아간다.
  - **팔레트가 열린 채 빈 곳을 끌면 뒤의 문서가 스크롤된다. 그대로 둔다**(2026-09-26 사용자 결정). 열린 파일 메뉴에서는 같은 드래그를 막았지만, 팔레트는 뒤의 문서를 보면서 찾는 경우가 많아 막을 투명하게 둔 것과 같은 이유로 막지 않는다.
  - 입력 버튼을 위아래로 스와이프하면 모양과 모드가 바뀐다: `>` 커맨드 검색, 🔍 파일 검색, `@` 심볼 검색.
    - **셋 다 글자가 아니라 선 아이콘으로 그린다** (2026-09-21 사용자 요청). 상단 메뉴와 같은 방식(획 하나, `currentColor`, 채움 없음, 24px)이고, `topbar.ts`의 `svg()`를 함께 쓴다. 글자로 두면 🔍는 시스템이 제 색과 제 굵기로 칠하는 이모지라 혼자 튀고, `>`와 `@`는 폰트가 주는 굵기로 폰트의 베이스라인 자리에 앉는다 — 버튼 한가운데가 아니다.
    - `>`는 명령을 치는 줄까지 같이 그린 프롬프트(`>_`), `@`는 안쪽 원과 그 둘레를 돌다 멈추는 획이다.
- **C:** 입력을 시작하면 퍼지 검색 결과가 뜨고 맨 위 항목이 기본 선택이다.
  - Enter나 입력 버튼으로 실행하고 A로 돌아간다.
  - A로 돌아갈 때 버튼 모양은 마지막 모드를 유지한다.
- **B는 비어 있지 않다** (2026-09-21 사용자 요청): 아무것도 치기 전에 **그 모드에서 마지막으로 실행한 다섯 개**를 보여주고, 타이핑 없이 거기서 바로 실행할 수 있다. 모드마다 따로 세고, 같은 것을 다시 실행하면 목록에서 한 자리만 차지하며 맨 위로 올라온다. 한 번도 실행한 적이 없는 모드에서는 아무것도 뜨지 않는다.
  - **페이지의 `localStorage`에 남는다**(`recents.ts`, 키는 `palette.recent`). 앱을 껐다 켜도, 액티비티가 재생성돼도 그대로다. `settings.toml`이 아닌 이유는 그 파일이 **사람이 열어 고치는 것**이기 때문이다 — 최근 목록은 편집할 설정이 아니라 쓰다 보면 쌓이는 흔적이라 페이지가 자기 쪽에 둔다.
  - 그러려면 `MainActivity`가 `domStorageEnabled`를 켜야 한다. **기본값이 꺼짐이고, 그때 `localStorage`는 null이라** `.setItem`이 `TypeError`로 떨어진다(기기에서 확인). 저장소는 이 앱의 origin 아래 앱 전용이고 앱 데이터를 지우면 같이 지워진다.
  - **저장소가 없어도 팔레트는 돌아간다.** 읽기와 쓰기 모두 실패를 삼키고 빈 목록으로 간다 — 저장소가 꺼진 빌드, 꽉 찬 저장소, 그리고 DOM이 없는 vitest가 전부 그 경로다. 남아 있던 것이 우리가 적은 모양이 아니면 없는 것으로 친다.
- **가로는 600px에서 멈추고 구석에 남는다** (2026-09-21 사용자 요청). 탭에서는 좌우 16px만 남기고 1120px까지 늘어나 있었다 — 한 줄이 화면을 가로지르면 엄지가 있는 버튼에서 멀고, 이름은 그렇게 길지 않다. 좁은 화면은 상한 아래라 전처럼 화면 너비를 다 쓴다(`width: calc(100% - 32px); max-width: 600px`).
- **결과 개수에는 상한을 두지 않는다**(2026-09-21 사용자 결정). 여덟 줄로 끊는 것을 넣었다가 뺐다. 길면 목록이 스크롤된다(`max-height: 40vh`).
- 파일 검색: 프로젝트에서는 `git ls-files`를, 단일 파일에서는 열린 파일과 같은 디렉토리를 대상으로 한다.
  - **목록은 팔레트를 열 때마다 한 번 받는다**(같은 디렉토리 목록과 같다). 추적하지 않는 파일은 HEAD가 그대로여도 생기고 사라지므로 열기 사이에 남겨 두지 않는다. 화면의 파일과 이미 열린 파일은 빠진다.
  - **git을 쓸 수 없는 프로젝트는 SFTP로 하위 폴더를 걷는다**(2026-10-03 사용자 결정). exec가 막힌 `internal-sftp` 계정, 서버에 git이 없는 경우, `ls-files`가 실패한 경우가 다 이쪽이다. 같은 프로젝트에서 git 유무로 검색 범위가 달라지지 않게 하려는 것이다.
    - **무엇을 빼고 어디서 멈출지는 `settings.toml`의 `[search]`다**(2026-10-03 사용자 결정): `skip_dirs`(들어가지 않을 폴더 이름, 기본 `node_modules`, `.venv`, `venv`, `__pycache__`, `.gradle`, `build`, `dist`, `target`)와 `max_files`(100~100000, 기본 5000). git이 있으면 둘 다 쓰지 않는다 — `.gitignore`가 정한다. `.git`은 목록과 관계없이 들어가지 않는다(사이드바 트리와 같다). `/`가 든 이름은 폴더 이름과 맞을 수 없으니 목록째 기본값으로 돌리고 알린다.
    - 상한에 닿으면 멈추고 배너로 알린다(어떤 파일이 없는 것을 버그로 읽지 않게). 깊이 상한은 없다. 폴더를 가리키는 심볼릭 링크는 따라가지 않아서 순환이 생기지 않는다. 파일을 가리키는 링크는 목록에 두고(아래 단일 파일의 결정과 같다), 그러려고 링크마다 `stat`을 한 번 한다 — SFTP 목록은 링크를 링크로만 알려 준다. 아무것도 가리키지 않는 링크는 뺀다. 루트 아래의 읽을 수 없는 폴더(권한 없음, 그새 지워짐)는 건너뛰고, 연결이 끊긴 것은 실패로 낸다 — 건너뛰면 남은 것을 프로젝트 전체로 보이게 된다.
  - 지운 프로젝트의 열린 파일은 단일 파일처럼 같은 디렉토리를 찾는다(거터를 잃는 것과 같은 규칙).
  - 단일 파일에서는 **다른 열린 파일이 먼저, 그다음 같은 디렉토리의 파일**이다(2026-09-26). 화면에 있는 파일, 디렉토리, 이미 열린 파일은 디렉토리 쪽에 다시 나오지 않는다. `content://`는 디렉토리가 없어 열린 파일만이다.
  - **디렉토리에서 고른 파일은 경로를 묻지 않고 연다.** 페이지는 이름만 보내고 Kotlin이 `/`·`..`가 든 이름을 거부하므로, 열리는 것은 사용자가 이미 연 파일 옆의 파일뿐이다. 링크의 경로 확인은 밖에서 온 경로를 위한 것이다.
  - 디렉토리는 팔레트가 열릴 때마다 한 번 읽고, 이름이 도착하면 치던 질의를 다시 찾는다.
  - **파일을 가리키는 심볼릭 링크도 목록에 둔다**(2026-09-26 사용자 결정). 고르면 링크가 가리키는 파일이 열리고 저장도 그리로 간다 — 디렉토리 밖일 수 있지만, 사용자가 이름을 보고 고른 것이고 링크로 열 때나 다른 편집기와 같다.
  - **프로젝트가 활성이면 기준은 열린 파일의 폴더가 아니라 그 프로젝트이고, 하위 폴더까지 전부 찾는다**(2026-09-26 사용자 요청). 같은 이름이 여러 폴더에 흔해지므로 항목은 프로젝트 루트에서의 상대 경로(`src/main.ts`)로 보이고, 퍼지 검색도 그 경로에 건다.
- 심볼 검색: **LSP가 있으면 LSP를, 없으면 lezer 구문 트리를 쓴다**(2026-09-27 사용자 결정). 기준은 "프로젝트냐"가 아니라 "LSP가 붙어 있느냐"다.
  - 심볼의 질은 LSP가 낫다(계층, 종류, 범위, 프로젝트 전체). 하지만 LSP가 뜰 수 없는 파일이 많다 — 기기 로컬 파일과 `content://`, 셸 없는 `internal-sftp` 계정, 서버에 언어 서버가 없는 경우, 프로젝트 없이 링크로 연 파일. Markdown 제목도 LSP로는 거의 안 나온다. 그래서 lezer는 **LSP가 없을 때의 작은 대체 수단**이다.
  - 심볼 모양은 처음부터 **LSP `DocumentSymbol`을 따른다**(이름, 종류, 줄, 자식). M6에서 LSP가 붙으면 팔레트는 그대로 두고 공급원만 바꾼다.
  - **LSP 쪽(M6)은 한 목록이다**(2026-10-06 사용자 결정). 위에 이 파일의 개요(`textDocument/documentSymbol`, 팔레트를 열 때 한 번), 아래에 입력한 것으로 서버에 물은 프로젝트 심볼(`workspace/symbol`)이 그 파일의 루트 기준 경로와 함께 붙는다. 아래쪽에서 화면의 파일은 뺀다. 퍼지 점수가 높아도 프로젝트 심볼은 이 파일 심볼 아래다. 아무것도 입력하지 않으면 지금처럼 최근 항목만 보인다.
    - 프로젝트 심볼은 입력할 때마다 묻되 **한 번에 하나만** 묻는다. 답을 기다리는 동안 들어온 입력은 마지막 것만 남겨 두었다가 답이 오면 묻고, 그동안은 직전 답을 팔레트의 퍼지 검색이 좁혀 보여 준다.
    - 고르면 정의로 이동과 같은 `openDefinition`으로 그 파일의 줄·열에 연다(경로를 묻지 않는다, [LSP](lsp.md)의 "정의로 이동"과 같은 이유).
    - **변수는 파일 맨 위(모듈 수준)에 있을 때만 넣는다.** pyright는 함수의 인자와 지역 변수, 클래스 속성을 모두 kind 13(Variable)로 주고, `workspace/symbol`의 평평한 목록에서는 `containerName`만으로 함수 안인지 클래스 안인지 가를 수 없다. 지역 변수가 대부분이라 둘 다 뺐다. 파일 개요도 같은 규칙이고, 함수·메서드 안은 lezer처럼 통째로 뺀다.
    - 서버가 개요를 트리가 아니라 평평한 목록으로 주거나, 답하지 않거나, 실행 중이 아니면 그 파일은 lezer로 읽는다. 이때 배너는 띄우지 않는다 — 팔레트에는 어느 쪽이든 답이 있다.
    - **pyright는 `initialize`에 `workspaceFolders`가 없으면 `workspace/symbol`에 늘 빈 목록을 준다**(이 맥의 pyright로 봤다). 라이브러리는 `rootUri`만 보내므로, 페이지의 transport가 `initialize`에만 프로젝트 루트를 워크스페이스 폴더로 더한다(`withWorkspaceFolder`). pyright의 `/<default workspace root>` 로그도 이것으로 사라졌다. 개요를 트리로 받으려고 `hierarchicalDocumentSymbolSupport`도 알린다.
  - **lezer 쪽은 작게 잡는다:** 함수, 클래스, 메서드, Markdown 제목만. 변수, 상수, JSON/TOML 키, 인터페이스와 타입 별칭은 넣지 않는다 — LSP가 붙으면 대체될 것이라 언어마다 규칙을 늘릴 값이 적다. 언어는 TypeScript/JavaScript, Python, Markdown이다. 다른 언어는 LSP 전까지 비어 있다.
    - 함수에는 `const f = () => …`처럼 이름에 묶인 화살표 함수와 함수 식도 넣는다. 이 코드베이스부터 그렇게 쓴다.
    - 메서드는 클래스 안의 것만 본다. 함수 안에 선언한 함수는 넣지 않는다 — 대부분 잡음이다.
    - 팔레트에서 메서드는 `Class.method`로 보인다. 제목은 제목 글만 보인다.
- **팔레트 안쪽은 전부 영문이다** (2026-09-21 사용자 결정). 커맨드 이름(`Save File`), placeholder, "결과 없음"까지 팔레트라는 표면 하나가 통째로 영문이다. 커맨드 이름만 영문이면 한 줄 안에서 언어가 섞이고, 퍼지 검색의 대상도 영문 이름 하나가 된다(한글로 쳐서 커맨드를 찾는 길은 만들지 않는다).
  - 그래서 팔레트의 글자는 **Kotlin의 string resource를 거치지 않고 페이지 안에 있다.** 페이지의 다른 글자와 다른 유일한 자리다 — 지역화하지 않기로 한 것이라 `values-ko`가 들고 있을 것이 없다.
- **팔레트가 열릴 때 소프트 키보드를 영문으로** (2026-09-21): 강제하는 API는 없고 힌트뿐이다. **페이지만으로 됐다 — `inputmode="email"`이다.** 탭(삼성 키보드, 한국어와 English 둘 다 추가돼 있음)에서 잰 것:

  | 입력칸 | `EditorInfo` | 키보드 |
  |---|---|---|
  | `type=text` + `lang="en"` | `inputType=0x8c0a1`, **`hintLocales=null`** | 한국어 |
  | `type=url` / `inputmode=url` | `inputType=0x11` | 한국어 |
  | **`inputmode=email`** | `inputType=0xd1` | **English** |

  - **`lang="en"`은 IME에 닿지도 않는다.** Chromium이 `hintLocales`로 옮겨주지 않아 `null`이다. 그래서 페이지의 `lang`으로는 아무것도 못 한다.
  - 이메일 칸이 아니지만 **이메일 칸이 요구하는 모양이 커맨드 이름의 모양이다** — 라틴 문자, 자동수정 없음, 첫 글자 대문자 없음, 그리고 `@` 키(심볼 모드의 글리프이기도 하다).
  - **문서 쪽은 그대로 한국어다.** 문서를 탭하면 한국어, 팔레트를 열면 English로 바뀌는 것을 같은 세션에서 확인했다.
  - 다른 키보드가 무시하면 남은 길은 Kotlin의 `EditorInfo.hintLocales`(API 24+)다. WebView를 서브클래싱해 `onCreateInputConnection`의 `outAttrs`에 넣되, 그 자리가 페이지 전체에 하나뿐이라 **팔레트가 포커스를 잡고 놓을 때 브리지로 알려** 켜고 끄고 `imm.restartInput(webView)`로 다시 읽게 해야 한다.
  - **키보드 언어는 화면으로 못 읽는다**(삼성 키보드의 자판 영역은 `screencap`에 흰색으로 나온다). `adb shell dumpsys activity service com.samsung.android.honeyboard | grep currentLang`이 읽어 준다. 탭은 외장 키보드 때문에 소프트 키보드가 뜨지 않으므로 `settings put secure show_ime_with_hard_keyboard 1`로 띄우고 **끝나면 0으로 되돌린다.**

## 성공 조건

이 주제가 됐다고 말할 수 있는 조건과 확인 방법이다(`AGENTS.md`). ✅는 충족, ⬜는 아직이다. 확인한 때와 자세한 내역은
[`skiffcode.plan.done.md`](../skiffcode.plan.done.md)의 그 마일스톤에 있다.
