# 마크다운 문서 링크

[목차](../skiffcode.spec.md)

렌더된 마크다운(viewer)에서 링크를 탭하면 그 링크를 연다. 원래 요구사항은 [`my.next.spec.md`](../my.next.spec.md)의
"markdown 문서 링크 열기"다. 지금까지는 상대 링크와 `#조각`이 아무것도 하지 않았고(페이지의 origin으로 풀려 갈 데가
없었다), 나머지는 WebView의 `shouldOverrideUrlLoading`이 다른 앱으로 넘겼다.

## 링크 종류와 하는 일

| 링크 | 하는 일 |
|---|---|
| 상대 경로 (`a.md`, `docs/a.md`, `../a.md`, `./src/main.py`) | 지금 문서의 폴더를 기준으로 풀어 **묻지 않고 앱에서 연다** |
| `/`로 시작하는 경로 (`/docs/a.md`) | 프로젝트면 프로젝트 루트 기준(GitHub과 같다), 단일 파일이면 서버(기기)의 절대 경로 |
| `#제목` | 같은 문서의 그 제목으로 간다 |
| `a.md#제목` | `a.md`를 열고 그 제목으로 간다 |
| `https://…/x.md` | 앱에서 **읽기 전용**으로 연다 |
| `https://github.com/<o>/<r>/blob/<ref>/<path>.md` | `raw.githubusercontent.com/<o>/<r>/<ref>/<path>.md`로 바꿔 앱에서 연다 |
| 그 밖의 `https://`, `http://`, `mailto:` | 지금처럼 기본 앱으로 바로 넘긴다(고르는 창을 따로 띄우지 않는다) |
| 그 밖의 스킴 (`javascript:`, `file:`, `intent:`, `content:` …) | 아무것도 하지 않는다 |

- **상대 링크는 어디를 가리키든 묻지 않는다**(2026-10-15 사용자 결정). 사용자가 앱 안에서 직접 탭한 것이라 팔레트 파일
  모드, 사이드바, 정의로 이동과 같은 쪽으로 본다. 프로젝트 루트 밖(`../../`)도, 단일 파일의 폴더 밖도 그대로 연다.
  그래서 이것은 `AGENTS.md`의 "Links that arrive from outside"가 말하는 **페이지가 보낼 수 있는 것을 넓히는 일**이다.
  넓힌 대신 지키는 선:
  - 페이지는 **열린 문서의 id와 링크의 `href` 원문**만 보낸다. 경로를 푸는 것은 Kotlin이다. 기준은 늘 Kotlin이 든
    그 문서의 위치이고, 서버(프로필)는 그 문서의 것을 그대로 쓴다 — 링크가 다른 서버나 다른 계정을 고를 길은 없다.
  - 루트(`/`) 위로 올라가는 `..`는 거부한다. NUL이 든 경로도 거부한다.
  - 마크다운은 `html: false`이고 CSP가 스크립트를 막으므로, 문서가 페이지를 움직여 링크를 대신 "누르게" 할 길은 없다.
    탭은 사람의 것이다.
- **텍스트면 확장자와 상관없이 앱에서 연다**(2026-10-15 사용자 결정). `.py`, `.toml`도 코드 viewer로 열린다. 텍스트인지는
  지금처럼 `TextLoader`가 내용을 보고 정한다 — 이미지나 PDF는 바이너리 안내, 큰 파일은 크기 안내, 폴더는 "폴더" 오류,
  없는 파일은 여는 흐름의 오류 문구가 그대로 나온다.
- **`content://` 문서에는 폴더가 없다**(한 파일에 대한 권한이다). 그 안의 상대 링크와 `/` 링크는 아무것도 하지 않는다.
  `#제목`은 된다.
- 경로는 퍼센트 인코딩을 풀어서 쓴다(`my%20doc.md`). 상대 링크의 `?쿼리`는 버린다.

## 제목으로 가기

- 제목의 이름(앵커)은 **GitHub과 같은 규칙**으로 만든다: 글자를 소문자로, 글자·숫자·`-`·`_`·공백 밖의 문장부호를 지우고,
  공백을 `-`로. 한글은 그대로 둔다. 같은 이름이 또 나오면 `-1`, `-2`를 붙인다. 계산은 페이지가 한다(`web/src/markdown.ts`).
- 찾은 제목의 원본 줄로 `goToLine`한다. 렌더된 마크다운의 맨 위 블록마다 `data-line`이 있으므로, 링크의 `?line=`이나
  점프 목록과 같은 한 길이다. 못 찾으면 문서 맨 위에 둔다.
- 다른 문서의 `#제목`은 Kotlin이 여는 요청(`OpenAt`)에 조각을 실어 보내고, 문서가 페이지에 닿으면 페이지가 위의 방법으로
  줄을 찾는다.

## 점프 목록

- 링크로 다른 문서를 열면 [점프 목록](jumps.md)의 "화면의 파일이 바뀔 때"로 적힌다(`reconcile`을 지난다).
- 같은 문서의 `#제목`은 "같은 파일 안에서 줄을 옮길 때"로, `goToLine` 바로 앞에서 적는다.
- 그래서 오른쪽 가장자리에서 밀면 링크를 누르기 전 자리로 돌아온다.

## https 마크다운 (웹 문서)

- **읽기 전용이다**(2026-10-15 사용자 결정). viewer만 있고 editor·diff로 가지 않는다(③이 레이어를 바꾸지 않는다).
  저장, 바뀜 감시, git 거터, LSP가 없다.
- 열린 파일 메뉴와 팔레트에는 주소의 호스트와 경로로 보인다. **최근 파일에는 남기지 않는다** — 최근 파일은
  `skiffcode://` 링크로 다시 여는 목록이고, 웹 문서는 그 모양이 없다. 같은 주소는 열린 파일 하나로 간다.
- 받기는 Kotlin이 한다(페이지의 CSP와 로더는 외부 네트워크를 막는 그대로 둔다). `HttpURLConnection`, 새 의존성 없음:
  - `https`만 받는다. Android가 평문 http를 막으므로 `http://…/x.md`는 다른 https 링크처럼 기본 앱으로 넘긴다.
  - 쿠키와 자격증명을 보내지 않는다. 넘김은 https 안에서만 따라간다(`HttpURLConnection`의 기본).
  - 응답의 `Content-Type`이 `text/html`이면 마크다운이 아니라 웹 페이지라 열지 않고 그렇게 알린다.
  - 크기 상한과 글자 인코딩은 원격 파일과 같은 `TextLoader` 규칙을 쓴다.
  - 연결·읽기 시간 제한을 둔다. 실패는 여는 흐름의 오류 문구와 같은 자리에 보인다.
- `.md`인지는 주소의 경로 끝으로 본다(대소문자 무시, 쿼리와 조각은 빼고).
- 웹 문서 안의 상대 링크는 그 주소를 기준으로 푼다. 풀린 주소가 `.md`면 다시 웹 문서로, 아니면 기본 앱으로 간다.
  GitHub 변환 뒤의 raw 주소가 기준이므로 같은 레포의 다른 `.md`도 raw로 이어진다.
- 내용의 위험은 원격 파일과 같다: `html: false`, CSP가 외부 이미지(추적 픽셀)를 막는다.
- 경로 확인 창(`OpenFlow.confirmPath`)은 이 종류를 따로 적는다: 앱 안의 탭에서만 생기고 바깥 링크(`skiffcode://`,
  https 링크)로는 만들 수 없으므로 묻지 않는다.

## 성공 조건

이 주제가 됐다고 말할 수 있는 조건과 확인 방법이다(`AGENTS.md`). ✅는 충족, ⬜는 아직이다. 확인한 때와 자세한 내역은
[`skiffcode.plan.done.md`](../skiffcode.plan.done.md)의 그 마일스톤에 있다.

- ⬜ 링크 해석이 위 표대로다 — 확인: JVM(상대·하위·`../`·`/`의 프로젝트와 단일 파일·퍼센트 인코딩·쿼리 버림·조각 유지·루트 위 `..` 거부·NUL 거부,
  `content://` 기준은 무시, https `.md`(대소문자, 쿼리·조각), GitHub blob → raw, https·http·mailto는 기본 앱, 그 밖의 스킴은 무시,
  웹 문서 기준의 상대 링크).
- ⬜ 제목 앵커가 GitHub 규칙과 같다(한글, 문장부호, 중복) — 확인: vitest.
- ⬜ 웹 문서 받기가 `text/html`을 거부하고, 상한을 넘으면 크기 안내, 실패는 문구 — 확인: JVM의 로컬 HTTP 서버.
- ⬜ 원격 프로젝트와 단일 파일, 로컬 파일에서 상대 링크가 묻지 않고 열리고, `#제목`과 `a.md#제목`이 그 제목으로 가며, 오른쪽 가장자리 밀기로 돌아온다 — 확인: 탭.
- ⬜ https `.md`와 GitHub blob 링크가 읽기 전용으로 열리고 그 안의 상대 `.md`도 이어진다. 다른 https와 mailto는 기본 앱으로 간다 — 확인: 탭.
- ⬜ 좁은 화면에서도 링크가 눌린다 — 확인: 폴드8 커버 화면.
